# Мангалы — промо-сайт

Промо-сайт производителя мангалов в эстетике шутеров начала девяностых: витрина-арсенал,
корзина как нижняя HUD-панель, заявка вместо оплаты. Весь контент правится из админки.

Реализованы **этапы 1–5** ТЗ: каркас, витрина, HUD-корзина, оформление заказа, админка.
Что осталось — в разделе [Не сделано](#не-сделано).

---

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # заполнить AUTH_SECRET и SEED_ADMIN_PASSWORD
npm run db:migrate
npm run db:seed
npm run dev
```

Витрина: http://localhost:3000 · Админка: http://localhost:3000/admin

`AUTH_SECRET` — не короче 32 символов:

```bash
openssl rand -base64 32
```

## Стек

Next.js 15 (App Router) · React 19 · TypeScript strict · Tailwind CSS v4 ·
Zustand + persist · React Hook Form + Zod · Drizzle ORM · SQLite (better-sqlite3) ·
jose (сессии) · hash-wasm (argon2id).

**Почему SQLite, а не Postgres.** ТЗ допускает это как альтернативу (п. 3). Проект
поднимается локально одной командой, без внешних сервисов и ключей. Схема Drizzle
переносится на Postgres/Neon сменой диалекта в `lib/db/schema.ts` и `drizzle.config.ts`;
кода приложения это не касается. На Turso меняется только строка подключения.

## Структура

```
app/
  (site)/              витрина: главная, карточка, корзина, оформление, подтверждение
    @modal/(.)product/ перехватывающий маршрут — карточка модалкой поверх арсенала
  admin/               админка: вход, товары, заявки, настройки
  api/admin/           загрузка спрайтов, выгрузка заявок в CSV
actions/               Server Actions (заказ, авторизация, CRUD, настройки)
components/
  hud/                 HUD-корзина и морда мангала
  storefront/          hero, арсенал, карточка, форма заказа
  ui/                  пиксельные примитивы: кнопка, панель, степпер, модалка
  admin/               обычный интерфейс админки
lib/
  db/                  схема и клиент Drizzle
  cart/                стор корзины и чистые функции подсчёта
  auth/                argon2id, JWT-сессии, проверка прав
  notify/              письма (Resend) и Telegram
  markdown/            безопасный рендер описаний
scripts/               генератор спрайтов, миграции, сиды, снимок контента
content/demo.json      контент для сборок без базы (CI)
```

**Про расширение `.server.tsx`.** Маршруты, которым нужен сервер — оформление
заказа, подтверждение, вся админка, Route Handlers, middleware — лежат в файлах
`page.server.tsx` / `route.server.ts` / `middleware.server.ts`. Обычная сборка
считает такие файлы маршрутами (`pageExtensions` в `next.config.ts`), а
демо-сборка под GitHub Pages — нет, поэтому серверный код в статический экспорт
просто не попадает. Это единственная причина необычных имён.

## Ключевые решения

**Цены считает сервер.** Корзина в `localStorage` хранит только `productId` и `qty`.
При создании заказа сервер заново читает товары, проверяет `isActive` и `inStock`,
пересчитывает сумму и кладёт в `orderItems` снимок цены. Клиентский итог — только
для отображения, о чём прямо сказано в интерфейсе.

**Заявка не теряется.** Письма и Telegram отправляются после сохранения заказа,
с тремя попытками. Упавшая отправка логируется, но не роняет ответ клиенту.
Если ключи не заданы, отправка тихо пропускается — заказ всё равно создаётся.

**Идемпотентность.** Форма генерирует ключ при монтировании и шлёт его с заявкой.
Повторный сабмит возвращает тот же номер заказа, а не создаёт второй.

**Антиспам.** Honeypot-поле, проверка времени заполнения (быстрее 2 с — бот),
5 заявок в час на IP. Для входа в админку: 5 попыток за 15 минут, дальше IP
блокируется на час.

**Шрифт.** ТЗ предупреждало о кириллице в пиксельных шрифтах — предупреждение
подтвердилось. Pixelify Sans рисует кириллическую **К** с лишним штрихом
(«СТАЛЌЕР», «ЗАЯВЌИ»), поэтому взят **Handjet**: те же строки он рисует ровно,
лицензия открытая, есть latin и cyrillic.

**Токены тем заданы ролями.** `--surface` — фон панели, `--edge-light` и `--edge-dark` —
грани объёмной рамки. Без этого светлая тема `blocks` ломается: в тёмной теме
самый тёмный токен служит и фоном панели, и тенью, а в светлой это противоположные
цвета. Обе темы переключаются атрибутом `data-theme` из админки, компоненты не меняются.

**Единица сетки — 8px.** В Tailwind это `--spacing: 0.5rem`, поэтому `p-2` — это 16px,
`gap-1` — 8px. Тач-таргеты и фиксированные колонки заданы явными пикселями
(`min-h-[44px]`), чтобы не зависеть от этой единицы. У админки своя единица 4px —
она задана на её обёртке.

**Спрайты — собственные.** Вся пиксель-графика генерируется кодом
(`scripts/gen-sprites.mjs` + собственный PNG-энкодер на `zlib`): 8 мангалов, 4 кадра
морды, 4 иконки, спрайт-лист hero. Всё вместе — **9,3 КБ** при бюджете 300 КБ.
Чужих ассетов в проекте нет.

**Анимация hero без JS.** Шесть кадров лежат одним спрайт-листом, покадровая
анимация делается CSS-шагами. Поэтому «спокойный режим» гасит её правилом
`animation: none`, а `prefers-reduced-motion` работает до гидрации и без скриптов.

## Безопасность

- Все Server Actions сами проверяют сессию — отсутствие кнопки в UI за защиту не считается.
- Zod-валидация всех входных данных на сервере, включая `qty` (1–99) и длины строк.
- Загрузка спрайтов: проверка магических байтов PNG (а не `Content-Type`), лимиты
  512×512 и 200 КБ, имя файла заменяется на UUID, эвристика «это фотка, а не пиксель-арт».
- Пароли — argon2id (19 МиБ, 2 прохода). Сессия — JWT в httpOnly + SameSite=Lax cookie на 7 дней.
- Описания товаров рендерятся собственным парсером markdown в React-узлы, без
  `dangerouslySetInnerHTML` — XSS-поверхности нет.

**Про CSP — важный компромисс.** App Router встраивает RSC-payload инлайновыми
`<script>`. Убрать `unsafe-inline` можно только через nonce, а nonce несовместим со
статической генерацией: витрина стала бы динамической и потеряла ISR и целевой LCP.
Поэтому строгий nonce-CSP включён **только для `/admin/*`** (`middleware.ts`) — там
страницы и так динамические, а риск выше. Для витрины CSP оставляет `unsafe-inline`
для скриптов; собственных инлайновых скриптов в проекте нет, JSON-LD не исполняется.
Решение стоит проговорить с заказчиком: полностью строгий CSP покупается отказом от SSG.

## Доступность

Фокус видимый и стилизованный, `outline: none` не используется. Модалка — `role="dialog"`
с ловушкой фокуса, закрытием по `Esc` и возвратом фокуса на инициатор; фокус ставится
на сам диалог, а не на кнопку закрытия, иначе `Enter` закрывал бы карточку вместо
«взять». Счётчик позиций в HUD озвучивается через `aria-live`, добавление в корзину —
через `role="status"`. Шкалы характеристик — `role="meter"`. Хоткеи `1`–`9` не
перехватываются, когда фокус в поле ввода. `alt` спрайта — обязательное поле в админке.

## Инструкция менеджеру

**Заявки.** `/admin/orders` — список с фильтром по статусу и датам. Клик по номеру
открывает карточку: контакты, состав, технические данные. Там же меняется статус и
пишется заметка. Кнопка «Выгрузить CSV» отдаёт то, что сейчас в фильтре, — файл
открывается в Excel без плясок с кодировкой.

**Товары.** `/admin/products` — таблица. Порядок слотов на витрине задаётся
перетаскиванием строки или стрелками (стрелки работают с клавиатуры), после чего
нужно нажать «Сохранить порядок слотов». Кнопка «В архив» убирает товар с витрины,
но он остаётся в истории заказов; вернуть можно из блока «Архив».

**Карточка товара.** Справа — живое превью ровно теми же компонентами, что на витрине.
Спрайт: PNG до 512×512 и 200 КБ, квадратный. Если картинка похожа на фотографию,
админка предупредит. Поле «описание спрайта» обязательно — это то, что прочитает
незрячий посетитель.

**Настройки.** `/admin/settings` — тексты первого экрана, контакты, блоки
«Производство», темы писем, тема оформления сайта. Изменения появляются на витрине сразу.

## Демо на GitHub Pages

Витрина опубликована статическим экспортом: https://cerutisi.github.io/mangal/

**Что работает:** hero с анимацией, арсенал, карточки товаров, хоткеи `1`–`9`,
HUD-корзина со счётом, степперами и суммой, обе темы, спокойный режим, SEO-разметка.

**Чего там нет и быть не может:** оформления заказа, страницы подтверждения и
всей админки. На Pages нет серверного процесса, а значит нет Server Actions,
Route Handlers, middleware и базы. Кнопка «Оформить» в демо превращается в
«Связаться» и ведёт к контактам.

Публикация автоматическая: пуш в `main` запускает
[`.github/workflows/pages.yml`](.github/workflows/pages.yml). CI собирает базу с
нуля из `content/demo.json`, делает экспорт и деплоит `out/`.

### Первое включение

Workflow пытается включить Pages сам (`enablement: true` у `configure-pages`).
Если он всё-таки падает с `Get Pages site failed ... Not Found`, включите вручную:
**Settings → Pages → Build and deployment → Source → GitHub Actions**, затем
перезапустите workflow.

Для приватного репозитория на бесплатном тарифе Pages недоступны — репозиторий
нужно сделать публичным.

### Как обновить контент демо

Контент в CI берётся не из вашей локальной базы (её там нет), а из снимка:

```bash
npm run content:export        # выгрузит правки из локальной админки
git add content/demo.json public/sprites/uploads
git commit -m "Обновил каталог демо"
git push
```

Загруженные через админку спрайты лежат в `public/sprites/uploads/` и
отслеживаются git — иначе на демо будут битые картинки.

### Адрес и свой домен

Сайт живёт в подкаталоге `/mangal`, поэтому в workflow задан
`NEXT_PUBLIC_BASE_PATH: /mangal`. Он же подставляется в пути к спрайтам —
и в CSS, и в `next/image`: с `unoptimized` компонент отдаёт `src` как есть и
basePath сам не приписывает, поэтому это делает `asset()` в `lib/demo.ts`.
Любая новая картинка из `public/` должна проходить через `Sprite` или `asset()`,
иначе на Pages она уйдёт в корень домена мимо подкаталога.
Если подключите свой домен — очистите эту переменную и `NEXT_PUBLIC_SITE_URL`
поправьте на новый адрес.

### Проверить экспорт локально

```bash
NEXT_PUBLIC_BASE_PATH=/mangal npm run build:demo
```

Готовые файлы — в `out/`. Открывать их напрямую из файловой системы бесполезно:
из-за `basePath` нужен HTTP-сервер, где сайт лежит в каталоге `mangal/`.

## Не сделано

Осознанно вне этого захода — этапы 6 и 7 ТЗ:

- звуки (клик, добавление, отправка) и тумблер в футере;
- CRT-слой: развёртка, виньетка, дрожание (тумблер «спокойный режим» уже работает
  и гасит анимации, включая `prefers-reduced-motion`);
- OG-картинки через `next/og` отдельно на товар;
- Sentry на клиенте и сервере;
- тесты: Vitest на расчёты корзины и Zod-схемы, Playwright на сценарии, axe-core в CI;
- ручная проверка iOS Safari (`position: fixed` у HUD при открытой клавиатуре).

Хранилище спрайтов сейчас — локальная файловая система (`public/sprites/uploads`).
На Vercel файловая система только для чтения: перед деплоем загрузку нужно перевести
на Vercel Blob или S3. Точка замены одна — `app/api/admin/upload/route.ts`.
